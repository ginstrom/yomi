# Sprites (sprite-tool)

Guidance for working in `art/`, the text sources of every sprite in the game. The root `CLAUDE.md` covers the rest of the project. Commands here are run from the repository root. `docs/reference/sprites.md` has the canvases and scales of each kind of sprite, the build's two targets, the animation frames, the hero's layer regions (fist box, grip point, face) and the battle effects' conventions: read it before drawing a unit, gear or an effect.

Sprites are made with [sprite-tool](https://github.com/ginstrom/sprite-tool) (`uv tool install git+https://github.com/ginstrom/sprite-tool@v0.6.0`; add `--force` to upgrade a copy already installed), which is installed on the host and is not in the podman image. Run `sprite guide --project art` before drawing or changing one: it prints the file format, the palette and the canvas classes.

- Sources are text in `art/**/<id>.sprite.toml`; `art/sprite-tool.toml` holds the canvas classes and the export target. Create one with `sprite new <kind> --canvas unit --project art --dir units`, where the id is the `UnitKind` (and so the name the atlas shows it by), or with `sprite new icon_<id> --canvas icon --project art --dir icons --runs` for a sprite started as runs.
- A frame is written as a grid, one character per pixel, or as runs: `[frames.<name>.runs]`, then one line per row that has pixels, each a list of `[column, "pixels"]`. Runs suit a sprite that is mostly empty, which is most of them on the 32px canvases. With `outline = "auto"` at the top of the file, draw only the interior and the tool adds the `k` outline. Do not write a script to generate a grid: placing pixels at a row and column is what runs do.
- An item that differs from another only in colour is a `[variants.<name>]` table in that icon's file (`swap = { <key> = "<key>" }`, built as `<id>_<name>.png`), not a new file.
- Loop: `sprite check --project art` until it prints `ok`; `sprite show <id> --project art` to read the result as text, outline included (`--frame <name> --diff` prints only the rows a frame changes from the one it is derived from); `sprite preview <id> --grid --project art` for the colours, looking at the PNG it names (`--on warrior` shows gear over the body, `--points` marks the points); then `npm run sprites`.
- Commit everything the build writes into `public/assets/sprites/`, `.sprite-tool-manifest.json` included, with the source; never edit an exported file by hand. `npm run sprites:check` fails when they are stale.
- Movement is frames and an `[anim.<name>]` in the sprite's own file; the scenes only say which animation plays. A unit needs `idle` and `walk`; a map sprite has `idle`.
- A unit names the middle of its body `[points] chest`, where shots and spells are aimed and fly from; every unit kind needs one. In a file with a top-level `outline = "auto"`, put `[points]` below it, or TOML reads `outline` as a point.
- A gear sprite (`gear/gear_<icon>`, on the `unit` canvas) says `over = "warrior"`, has `[anim.idle]` `like = "warrior"` and `[anim.walk]` `rest = true`, and keeps out of the body's fist, off-hand and face regions. A new weapon, shield, armour, head or cloak icon needs a sprite and an entry in `GEAR_SPRITES` or `WORN_SPRITES` (`src/scenes/unitLook.ts`), or `unitLook.test.ts` fails.
- The tool only overwrites files listed in the manifest, and every PNG in `public/assets/sprites/` is on it. A PNG put there by hand stops the build for a sprite with the same id; replacing one deliberately takes a one-off `sprite build --adopt --project art`, plus an update to the sprites `README.md`.
- Adding sprites: record provenance and licence in `public/assets/sprites/README.md`. A new portrait needs an id in `PORTRAIT_IDS`; a new location kind a `map_<kind>` sprite in `LOCATION_SPRITES`; a new facility its `camp_<facility>` sprite in `FACILITY_SPRITES`.
- `art/units/warrior.sprite.toml.example` is the tool's sample sprite, renamed so it is not built. It is a format reference, not the game's warrior.

When a canvas class, a sprite directory or a step of this workflow changes, update this file (and `docs/reference/sprites.md`) in the same commit.
