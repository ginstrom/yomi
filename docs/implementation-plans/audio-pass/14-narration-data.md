# Step 14: Narration data model and exporter

[Index](index.md) · [Design](../../designs/audio-pass.md) §4.5, §4.6, §5.8.1, §5.8.2, §5.8.5 · [Feature record](../../features/audio-pass.md)

## Objective

A cutscene beat can declare a voiced line (line id, voice, emotion, intensity, spoken wording, take); the rules for voiced lines are enforced by vitest; a Node exporter turns the voiced beats into a job list with a stable input hash per line; and a test fails whenever a voiced line's hash no longer matches the committed voice manifest. No beat is voiced yet (step 16 voices `intro.opening` and `source.sighted`), so the staleness test is vacuous on the real content and proven on fixtures. Covers R11 and the Node half of R12 (AC11, AC12's test part).

## Requirements and context

- **R11:** a beat is voiced by declaring a line id, a voice, an emotion and optionally an intensity, a spoken wording and a take. A voiced line never speaks a player-chosen template. The leader is never voiced (decision D4).
- **R12 (this step's part):** `npm test` fails when a voiced line is stale (its inputs changed since it was rendered). The Python render (`yomi-audio voice render`) is step 16; this step only writes the jobs it will read and the test that checks its manifest.
- **Tutorial tips are not voiced in v1** (design §4.6): the exporter reads `CUTSCENES` only. Do not add fields to `TUTORIAL`.
- **Templated text:** cutscene text and speakers may contain `{leader}` and `{encampment}` (filled at runtime by `fillText` in `src/story/story.ts`), which cannot be pre-rendered. A voiced beat must speak a template-free `spoken` wording or stay unvoiced. Nonverbal tags live only in `spoken`, which is never displayed, so `fillText` needs no change.
- **AC11** (each case its own test): vitest refuses a duplicate line id; `line` without `voice`; a voiced `{leader}` beat; spoken text with `{encampment}`; an unknown tag; a tag for a non-tag engine; an emotion the voice lacks.
- **AC12 (test part):** every voiced beat's `lineHash` equals the manifest's and its files exist; changing a voiced beat's spoken text without rendering fails the test.

### C11. Narration data

```ts
// src/story/cutscenes.ts: CutsceneBeat gains (design §5.8.1)
line?: string; voice?: VoiceId; emotion?: Emotion; intensity?: number; spoken?: string; take?: number
// src/story/narration.ts (Phaser-free; may import node:crypto and node:fs: only tests and scripts import it, never a scene)
export type VoiceId = 'narrator'
export type Emotion = 'neutral' | 'warm' | 'grave' | 'tense' | 'afraid' | 'angry' | 'sad' | 'triumphant' | 'whisper'
export const EMOTIONS: readonly Emotion[]
export const NONVERBAL_TAGS: readonly string[]          // '[sigh]', '[laugh]', '[chuckle]', '[gasp]', '[cough]'
export const TAG_ENGINES: readonly string[]             // ['chatterbox_turbo']
export interface VoiceTable { engine: string; model: string; revision: string; emotions: Emotion[]; params?: Record<string, unknown>; clips?: Partial<Record<Emotion, string>>; [k: string]: unknown }
export interface VoiceRegistry { adapter_version: number; voices: Record<string, VoiceTable> }
export function readVoices(path?: string): VoiceRegistry                    // smol-toml
export function spokenText(beat: CutsceneBeat): string                      // beat.spoken ?? beat.text
export function lineSeed(line: string, take: number): number                // first 32 bits of SHA-256(`${line}#${take}`)
export function lineHash(beat: CutsceneBeat, voice: VoiceTable, clipHashes: Record<string, string>, adapterVersion: number, voiceSettings: Record<string, unknown>): string
export interface VoicedLine { cutscene: string; index: number; beat: CutsceneBeat }
export function voicedLines(cutscenes: Record<string, Cutscene>): VoicedLine[]
export function narrationProblems(cutscenes: Record<string, Cutscene>, voices: VoiceRegistry): string[]   // design §5.8.1 rules; [] when clean
export function staleLines(lines: readonly VoicedLine[], manifest: VoiceManifest, hashOf: (line: VoicedLine) => string, fileExists: (path: string) => boolean): string[]   // AC12 check: ids of voiced lines missing from the manifest, with another hash, or without both files; [] when fresh
export interface VoiceManifest { version: 1; lines: Record<string, { hash: string; durationMs: number; voice: string; engine: string }> }   // storyAudio.ts takes it with `import type` only
```

- `lineHash` = SHA-256 hex of canonical JSON (keys sorted at every level) of `{ spoken, emotion (default 'neutral'), intensity (default 0.5), take (default 0), voice: <the table>, clips: <SHA-256 of each of the voice's clips, by emotion>, adapter_version, voice_settings: audio.toml [voice] }`.
- `audio/narration.jobs.json` (gitignored), written by `scripts/narration.ts`: `{ "adapter_version": n, "voice_settings": {…}, "jobs": [ { "line", "spoken", "voice": "<id>", "voiceTable": {…}, "emotion", "intensity", "take", "seed", "hash" } ] }`.
- `audio/voice.manifest.json` (committed; `{ "version": 1, "lines": {} }` from step 14): `{ "version": 1, "lines": { "intro.opening": { "hash": "…", "durationMs": 4120, "voice": "narrator", "engine": "chatterbox@<rev>" } } }`.
- `audio/voices.toml`: design §5.8.2 (`adapter_version`; `[narrator]` with `engine`, `model`, `revision`, `emotions`, `params`; `[narrator.design]`; `[narrator.clips]`; `[narrator.fallback]`). Step 14 writes it provisionally (narrator A's description, engine `chatterbox`, revision `"unpinned"`, no clips); step 15 finalises it from gate G1.
- Voice files `public/assets/voice/<line>.opus` and `.mp3`, loaded as `voice_<line>`.

npm script added by this step (C2): `"narration:export": "node scripts/narration.ts"`. Step 16 adds `narration` (export then render); do not add it here.

**Consumers:** step 15 rewrites `voices.toml` (pinned revisions, clips) and relies on `readVoices`; step 16's Python `voice render` reads `audio/narration.jobs.json` in exactly this shape and writes `audio/voice.manifest.json` in exactly this shape, then voices two beats; step 17's `storyAudio.ts` imports `audio/voice.manifest.json`.

## Scope and implementation guidance

### `src/story/cutscenes.ts`

Add the six optional fields to `CutsceneBeat`, with these doc comments (design §5.8.1):

```ts
/** A stable id for the spoken line, unique in the game ([a-z0-9_.]+), e.g. 'intro.opening'. Voiced only when set. */
line?: string
/** The voice that speaks it, from audio/voices.toml; required with `line`. Never for a `{leader}` speaker. */
voice?: VoiceId
/** One of the voice's emotions; 'neutral' when left out. */
emotion?: Emotion
/** 0 to 1, how strongly; 0.5 when left out. */
intensity?: number
/** What is spoken when the shown text cannot be: no `{…}` templates; may carry nonverbal tags. Defaults to `text`. */
spoken?: string
/** Bumped to render the line again with a new seed when a take has a flaw; 0 when left out. */
take?: number
```

Import `VoiceId` and `Emotion` as types from `./narration.ts` (`import type`, so the game bundle does not pull `node:crypto`; `verbatimModuleSyntax` requires `import type`). If a circular type import is awkward, define the two unions in a tiny type-only module and re-export them from `narration.ts`; either way the exported names and values are those of C11. **Do not voice any beat** and do not change any beat's text.

### `src/story/narration.ts` (new)

The C11 exports. Notes:

- `EMOTIONS` lists the nine in the order of the `Emotion` union. `NONVERBAL_TAGS` the five tags; `TAG_ENGINES` `['chatterbox_turbo']`.
- `readVoices(path = 'audio/voices.toml')` parses with `smol-toml`: every top-level table except scalar keys is a voice (its sub-tables `design`, `clips`, `fallback` stay inside the voice's table); returns `{ adapter_version, voices }`. Resolve the default path from the repository root (relative to this module's URL), not the cwd.
- `lineSeed`: SHA-256 of `` `${line}#${take}` ``, first 4 bytes as an unsigned 32-bit big-endian integer.
- `lineHash`: build the object of C11 with defaults applied, serialise as canonical JSON (objects' keys sorted at every depth, arrays kept in order, no whitespace), SHA-256 hex. Write a small `canonicalJson` helper (exported or not, your choice) and test it.
- `voicedLines`: beats with `line`, in cutscene key order then beat order.
- `narrationProblems` returns one human-readable message per problem, naming the cutscene, beat index and line id. Rules (design §5.8.1):
  1. line ids unique across all cutscenes and matching `/^[a-z0-9_.]+$/`;
  2. `voice` present when `line` is; `voice` (or any voiced field: `emotion`, `intensity`, `spoken`, `take`) without `line` is also a problem;
  3. the voice is a key of the registry;
  4. no voice on a beat whose `speaker` contains `{leader}` or whose `portrait` is `'leader'`;
  5. the spoken text (`spokenText`) contains no `{` or `}`;
  6. its bracketed tags (`[word]`) are only `NONVERBAL_TAGS`, and only when the voice's `engine` is in `TAG_ENGINES`;
  7. the emotion (default `neutral`) is in the voice's `emotions`;
  8. `intensity` within 0 to 1; `take` a non-negative integer;
  9. the spoken text is not empty after tags are removed and whitespace trimmed.

### `scripts/narration.ts` (new) and `package.json`

- Imports `CUTSCENES` and the `narration.ts` functions; reads `voices.toml` and the `[voice]` table of `audio/audio.toml` (with `smol-toml`); for each voiced line, hashes each of its voice's clip files (SHA-256 of the file bytes, by emotion; none now) and writes `audio/narration.jobs.json` in C11's shape (`voice` is the id, `voiceTable` the resolved table, `seed` from `lineSeed(line, take ?? 0)`, defaults applied to `emotion`, `intensity`, `take`).
- Refuses (exit non-zero, printing every message) when `narrationProblems` is not empty, or a voice's clip file listed in `clips` is missing.
- Prints how many jobs it wrote. With today's content it writes `"jobs": []`.
- Keep the file small; put logic in `narration.ts` so tests reach it. Export a pure `buildJobs(...)` from `narration.ts` or the script if useful (not part of C11; keep it out of the script's top level so a test can import it without running the export, or guard the run with `import.meta.main`-style check appropriate to Node 26).
- `package.json`: add devDependency `smol-toml` (MIT; `npm install -D smol-toml` under Node 26, committing the lockfile change) and the script `"narration:export": "node scripts/narration.ts"`.

## Verification

Write `src/story/narration.test.ts` first (domain project; it runs under Node, so `node:fs` and `node:crypto` work). Fixture cutscenes and a fixture registry are built in the test (a fixture voice `narrator` with engine `chatterbox` and one `turbo_voice` with engine `chatterbox_turbo`, emotions a subset).

- **AC11, each its own test**, each asserting `narrationProblems` returns a message naming the line: duplicate line id across two cutscenes; `line` without `voice`; a voiced beat with `speaker: '{leader}'`, and one with `portrait: 'leader'`; spoken text with `{encampment}`; an unknown tag (`[yawn]`); a known tag (`[sigh]`) on the `chatterbox` voice (allowed on `turbo_voice`: a clean case); an emotion the voice lacks (`angry`); intensity `1.5` and `-0.1`; spoken that is only `[sigh]` (empty after tags); a malformed id (`Intro Opening`); an unknown voice id; `voice` without `line`.
- **Clean cases:** a well-formed voiced beat gives `[]`; **the real `CUTSCENES` with `readVoices()` give `[]`**.
- **Registry consistency:** every voice id in `audio/voices.toml` is a `VoiceId` (the set of keys equals `['narrator']`); every listed emotion is in `EMOTIONS`; `adapter_version` is a positive integer.
- **Helpers:** `spokenText` prefers `spoken`; `lineSeed` is deterministic, in 0 to 2^32−1, and differs between takes; `canonicalJson` gives the same string for objects with keys in different orders (nested too); `lineHash` is stable across key order of the voice table, applies defaults (a beat without `emotion` hashes as one with `'neutral'`, likewise intensity 0.5 and take 0), and changes when any of spoken, emotion, intensity, take, a voice field, a clip hash, the adapter version or a voice setting changes.
- **Staleness (AC12 test part):** for every voiced line of the real `CUTSCENES`, the manifest has an entry whose `hash` equals the current `lineHash` and both `public/assets/voice/<line>.opus` and `.mp3` exist (vacuous now: no voiced lines). Prove the check with fixtures: the C11 helper `staleLines(lines: readonly VoicedLine[], manifest: VoiceManifest, hashOf: (line: VoicedLine) => string, fileExists: (path: string) => boolean): string[]` (ids of voiced lines missing from the manifest, with another hash, or without both files; `VoiceManifest` as C11) reports a fixture line whose manifest hash is wrong, one missing from the manifest, and passes when the hash matches; changing the fixture's spoken text makes a matching manifest stale.
- **Exporter:** a test runs the job-building function over fixtures and checks C11's job shape, the seed and the hash; running `PATH=/opt/homebrew/opt/node@26/bin:$PATH npm run narration:export` writes `audio/narration.jobs.json` with `"jobs": []` and exits 0 (record the output); with a deliberately bad beat in a scratch copy it would exit non-zero (cover this in the unit test of the refusal path, not by editing `CUTSCENES`).

- No scene changes: `npm run test:browser` is not required.
